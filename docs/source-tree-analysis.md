## Critical Folders

| Folder | Why it matters |
|---|---|
| `data/sheets/` | The editable source of truth. Every fact in the app originates here. Edits must pass the validator. |
| `data/derived/` | Build inputs regenerated by the validator — the app imports all 6 files. Stale = app ships stale geo/graph data. |
| `src/data/` | The entire data-access layer. `types.ts` and `dataStore.ts` are the two files an AI agent must read first. |
| `src/components/shared/` | The design system. Check here before writing any new UI (see [ui_rules.md](./ui_rules.md)). |
| `scripts/` | The only "backend": validation, derivation, audit tooling. Python 3.9+, stdlib-only. |
| `src/hooks/` | Page-level orchestration/business logic — pages stay thin, hooks do the computing. |

## Entry Points

- **App runtime:** `index.html:14` loads `/src/main.tsx` → mounts `<StrictMode><HashRouter><App/></HashRouter></StrictMode>`.
- **Data pipeline:** `python3 scripts/validate_canonical_data.py --data-dir data` (wrapped by `npm run data:validate`, which also runs before `npm run dev` and in the pre-commit hook).
- **CI:** `.github/workflows/deploy.yml` on push to `main`.

## File Organization Patterns

- Every component/page has a co-located `*.module.css` (CSS Modules), imported under a short alias (`s`, `lp`, `ed`, …).
- Domain types live only in `src/data/types.ts`; components import them via `dataStore.ts` re-exports.
- TSVs are imported with Vite `?raw` (bundled as strings at build time) — there is **no runtime data fetching** except the Bible API (`src/utils/bibleApi.ts`).
- Generated/derived artifacts are always separated from hand-curated ones (`data/derived/` vs `data/sheets/`; `dist/` vs `src/`).
