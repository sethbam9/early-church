## Executive Summary

The **Early Christianity Atlas** (`early-christianity-map`, repo `early-church`) is a fully static, client-only React SPA for exploring the geographic and doctrinal history of early Christianity (AD 33–800). There is **no backend, no database, and no runtime data fetching** (one exception: on-demand Bible passage text from bible-api.com). The entire evidence-backed dataset — 16 canonical TSV sheets plus 6 derived TSVs — is inlined into the JavaScript bundle at build time via Vite `?raw` imports. A 2,000-line stdlib-only Python validator is the project's "backend": it enforces referential/semantic integrity and regenerates the derived tables, and it gates both `npm run dev` and every git commit.

Three architectural decisions define the system:

1. **Build-time static data.** TSVs are bundled as strings and parsed once into a module-singleton `dataStore` with ~20 Map indexes. Deploy = rebuild.
2. **Claims as an EAV/RDF-like hub.** Every fact is a subject→predicate→object triple constrained by a 25-predicate registry, linked to passage evidence with roles and weights, and reviewed via a snapshot + append-only event log.
3. **Derive, don't assert.** Inferable facts (bishop⇒active, controls⇒present, proposition presence) are materialized by the pipeline into derived tables — and asserting them directly is a validation *error*.

## Routing

`src/main.tsx` mounts `StrictMode > HashRouter > App`. **`App.tsx` renders all five pages simultaneously** and toggles visibility with `display: contents|none` based on `useLocation().pathname` (`src/App.tsx:11-23`). Consequences:

- Page state (map position, graph layout, wiki selection) survives navigation for free.
- Leaflet cannot measure a hidden container, so `MapPage` carries `invalidateSize` timers and a 100/300/600 ms `fitBounds` retry cascade (`src/pages/MapPage.tsx:260-272, 351-383`). Any new page with size-sensitive rendering must handle the same.
- Real URLs are hash-based (`/#/graph?kind=…&id=…`); deep-link state is written with `window.history.replaceState` per page. Params: map `?d&kind&id&tab`, graph/wiki `?kind&id`, audit `?claimId|edgeId|filter`.

## State Management

- **`useAppStore`** (Zustand, `src/stores/appStore.ts`) holds map/timeline/selection/filter/panel UI state — ~20 fields, ~25 actions, no persistence middleware. Notable couplings: `setSelection` clears history and re-enables arcs; `setPanelTab` clears panel search; `toggleRightPanel` collapses expansion.
- **Graph and Wiki pages do not use the store** — each has a dedicated state hook (`useGraphPageState`, `useWikiPageState`) with local state + URL sync.
- **Domain data is never in React state.** It lives in the `dataStore` module singleton; hooks read it inside `useMemo` pipelines keyed on store slices.

## UI Architecture

- **Design system:** primitives + domain widgets in `src/components/shared/` (inventory: [component-inventory.md](./component-inventory.md)); rules and forbidden patterns: [ui_rules.md](./ui_rules.md).
- **Tokens:** `styles/tokens.css` defines surfaces/text/borders/accent/status/domain colors, spacing, radii, type scale, shadows, layout vars; `[data-theme="dark"]` overrides everything (parchment/amber ⇄ navy/blue). NavBar toggles `data-theme` on `<html>`.
- **Color duplication constraint:** Leaflet divIcons and inline SVG can't read CSS variables, so domain colors exist in **both** `tokens.css` and `entityConstants.ts` (`PRESENCE_COLORS`, `STANCE_COLORS`, `KIND_COLORS`) — change them in pairs. Place-kind SVG paths are shared between React icons and Leaflet markers via `buildPlaceKindIconSvg` (`shared/icons.tsx:70-104`).
- **Two markdown paths:** react-markdown only for `docs/user-guide.md` on GuidePage; all TSV/essay content goes through the custom `MarkdownRenderer` (wiki-link mentions, hover cards, Bible overlays, search highlighting).
- **Floating UI via portals:** hover cards, tooltips, BibleOverlay all `createPortal` to `document.body`.

## Map & Graph Subsystems

- **Map:** raw Leaflet created in a mount-only effect; two `layerGroup`s (markers, arcs); markers are `divIcon`s with raw SVG strings; selection ring + connection rings + "ghost" marker for a selected place absent from the active decade; playback interval `max(200, 1400/speed)` ms; selection auto-zoom compensates for panel width via pixel projection.
- **Graph:** nodes/edges built from active claims; force layout in pure TS (`utils/forceLayout.ts`, 100–220 ticks by size); Yen's algorithm for K-shortest paths and BFS for degrees-of-separation (`utils/pathFinder.ts`); SVG transform pan/zoom.

## Development Workflow & Quality Gates

Detail: [development-guide.md](./development-guide.md). The essential loop:

1. Edit data (`data/sheets/`) or code (`src/`).
2. `npm run dev` — **runs the Python validator first**; a data error blocks the dev server.
3. Commit — Husky pre-commit runs the validator again; derived tables are auto-regenerated and should be committed with the sheet changes.
4. Push to `main` — GitHub Actions builds (`tsc -b && vite build`) and deploys to GitHub Pages ([deployment-guide.md](./deployment-guide.md)).

## Testing Strategy

**There are no automated code tests** — no unit/component/E2E files, no test runner configured. The only automated verification is the data validator (schema/FK/enum/semantic checks on every dev start and commit) plus `tsc -b` type-checking inside the build. Risk is concentrated accordingly: data regressions are well-guarded; UI regressions are not. A test harness (Vitest + Playwright would fit the stack) is the most obvious infrastructure gap for future work.

## Architectural Invariants (for AI-assisted changes)

1. **Never hand-edit `data/derived/`** — regenerate via `npm run data:validate` (the validator auto-rewrites stale files; it also re-sorts sheets into canonical order).
2. **Every new fact is a claim** constrained by `predicate_types.tsv`; don't invent predicates without registering them. Don't assert facts the pipeline derives (R2/R5/R7/R8 are errors).
3. **Domain types live in `src/data/types.ts` only**; components receive them via `dataStore` re-exports.
4. **No runtime data fetching.** New data ships in TSVs through the pipeline, not from an API.
5. **UI work follows [ui_rules.md](./ui_rules.md)**: tokens + CSS Modules, shared primitives, business logic in hooks/utils (not components), colors duplicated to JS registries only when Leaflet/SVG needs them.
6. **Pages stay mounted** — guard size-sensitive rendering against hidden-container measurement.
