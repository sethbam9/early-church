## Target: GitHub Pages (static)

The app is a pure static site — any static host works. The configured pipeline deploys to **GitHub Pages from the `gh-pages` branch**.

## CI/CD Pipeline (`.github/workflows/deploy.yml`)

**"Deploy to GitHub Pages"** — the repo's only workflow:

| Aspect | Value |
|---|---|
| Trigger | `push` to `main` |
| Permissions | `contents: write` |
| Concurrency | group `pages-deploy`, cancel-in-progress |
| Runner | `ubuntu-latest`, Node 20 (setup-node@v4, npm cache) |
| Steps | checkout → `npm ci` → `npm run build` → SPA fallback (`cp dist/index.html dist/404.html`) → `touch dist/.nojekyll` → deploy `./dist` via `peaceiris/actions-gh-pages@v3` to `gh-pages` |

Notes:

- The build step exports `GITHUB_REPOSITORY`, which drives the Vite base path (below).
- `tsc -b` runs inside `npm run build`, so type errors fail the deploy. **There is no test or data-validation stage in CI** — the validator gate exists only locally (dev script + pre-commit hook).
- `404.html` + HashRouter make deep links work on Pages; `.nojekyll` prevents Jekyll processing.

## Base Path Logic (`vite.config.ts:5-8`)

```ts
base: process.env.GITHUB_REPOSITORY
  ? `/${process.env.GITHUB_REPOSITORY.split("/")[1]}/`   // "/early-church/" in CI
  : "/"                                                   // local dev/preview
```

If the repo is renamed or moved to a user/organization page, this logic keeps working automatically; for a custom domain at root, delete the conditional.

## PWA / Static Assets (`public/`)

`site.webmanifest` — name "Early Christianity Atlas", short name "EC Atlas", `display: standalone`, theme `#c47c3a`, background `#f5f0e8`, 192/512 android-chrome icons. Plus favicon set and `apple-touch-icon.png`. `index.html` wires the manifest and favicons. (No service worker — installable manifest only, no offline caching.)

## Deploying Elsewhere

`npm run build` → upload `dist/` to Netlify/Vercel/any static host. Requirements:

1. Ensure base path is `/` (unset `GITHUB_REPOSITORY` locally — the default).
2. No server config needed for routing (HashRouter), but keep a 404 → index fallback if you later switch to BrowserRouter.

## Environments & Secrets

None. No environment variables, no API keys — the only external calls are public (bible-api.com, CARTO tiles).
