# Development Guide

> Generated by BMad `document-project` (deep scan) on 2026-07-01. Part of the [generated documentation set](./index.md).

## Prerequisites

- **Node.js ≥ 18** (LTS) and **npm ≥ 9**
- **Python 3.9+** — the validator is **stdlib-only**; there is no `requirements.txt` and nothing to pip-install
- No database, no environment variables, no `.env` files

## Setup

```bash
git clone https://github.com/sethbam9/early-church
cd early-church
npm install          # also runs `husky install` via the prepare script
npm run dev          # validates data, then starts Vite at http://localhost:5173
```

## npm Scripts — what they actually do

| Script | Command | Notes |
|---|---|---|
| `dev` | `npm run data:validate && vite` | **Validator runs first** — a data error blocks the dev server. |
| `build` | `tsc -b && vite build` | Project-references typecheck, then production build to `dist/`. |
| `preview` | `vite preview` | Serve the built `dist/`. |
| `data:validate` | `python3 scripts/validate_canonical_data.py --data-dir data` | Integrity checks **and** derived-table regeneration. |
| `data:derive` | same as `data:validate` | Alias — derivation is part of validation. |
| `data:validate-full` | adds `--check-markdown --scan-root .` | Also validates `[[wiki-links]]`/OSIS across repo markdown. |
| `data:validate-sparse` | adds `--check-sparse` | Reports entities with ≤1 active claim link. |
| `prepare` | `husky install` | Git-hook installation (automatic on `npm install`). |

**Git hook:** `.husky/pre-commit` runs `npm run data:validate` — every commit is blocked on data validation.

**Heads-up:** the validator is *not read-only*. It re-sorts sheets into canonical order and rewrites stale derived tables. After editing `data/sheets/*.tsv`, expect (and commit) resulting changes in `data/derived/` and possibly re-sorted sheet rows. Exit code is 1 only on errors; warnings pass.

## TypeScript Layout

Solution-style project references (`tsconfig.json` has no own files):

- `tsconfig.app.json` — `src/`: ES2020, `strict`, `noUncheckedIndexedAccess`, `noFallthroughCasesInSwitch`, `moduleResolution: "Bundler"`, `jsx: react-jsx`, `noEmit`.
- `tsconfig.node.json` — `vite.config.ts` + `scripts/**/*.ts`: ES2022, node types.

No path aliases are configured — imports are relative.

## Common Tasks

### Change or add data (the primary workflow)

1. Read [predicate-playbook.md](./predicate-playbook.md) (choosing predicates), [evidence-policy.md](./evidence-policy.md) (linking evidence), [review-policy.md](./review-policy.md) (review rows). For AI-assisted batches follow [ai-batch-checklist.md](./ai-batch-checklist.md).
2. Edit `data/sheets/*.tsv` (tab-separated; entity IDs are kebab-case slugs; see [data-models.md](./data-models.md) for schemas and FK rules).
3. Run `npm run data:validate` (or `data:validate-full` if you touched markdown/wiki-links).
4. Commit sheets **plus** the regenerated `data/derived/*.tsv` together.

### Add or change UI

1. Read [ui_rules.md](./ui_rules.md) first — token contract, shared-component catalog, forbidden patterns, and the per-change checklist live there.
2. Reuse primitives from `src/components/shared/` ([component-inventory.md](./component-inventory.md)); business logic goes in `src/hooks/`/`src/utils/`, not components.
3. Remember the [architecture constraints](./architecture.md#architectural-invariants-for-ai-assisted-changes): pages stay mounted; Leaflet/SVG colors are duplicated in `entityConstants.ts`.

### Add a new domain type/field

1. Update the schema in `scripts/validate_canonical_data.py` (`SOURCE_HEADERS`/`DERIVED_HEADERS` + checks).
2. Mirror it in `src/data/types.ts` and the parse/index code in `src/data/dataStore.ts`.
3. Update the hand-written specs ([app-data.md](./app-data.md), [domain-models.md](./domain-models.md)) to stay normative.

## Testing

There is **no test suite** — no unit, component, or E2E tests, and no runner configured. Verification today = Python data validator + `tsc -b` during build. If adding tests, Vitest (unit) and Playwright (E2E) fit the Vite stack naturally.

## Gotchas

- `npm run dev` failing at startup usually means a **data** error, not a code error — read the validator output.
- Derived TSVs are build inputs; if the map/graph looks stale after data edits, you forgot to rerun validation.
- `scripts/__pycache__/` contains an orphaned `.pyc` from a deleted `generate_derived_tables.py` — derivation now lives inside the validator.
- `tsx` and `d3-dsv` are declared devDependencies but unused by any script.
- HashRouter URLs: share links look like `/#/wiki?kind=person&id=…`.
