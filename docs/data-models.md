The dataset is 22 TSV files: 16 hand-curated canonical sheets (`data/sheets/`) and 6 derived tables (`data/derived/`) regenerated deterministically by `scripts/validate_canonical_data.py`. The app bundles all 22 at build time via Vite `?raw` imports (`src/data/dataStore.ts:30-53`).

### The Claim Model (the crux)

`claims.tsv` columns: `claim_id, subject_type, subject_id, predicate_id, object_mode, object_type, object_id, value_text, value_number, value_year, value_boolean, year_start, year_end, context_place_id, certainty, claim_status, created_by, updated_at`.

- **Polymorphic references:** subject and object are `(type, id)` pairs resolved to a table by type. Valid entity types: place, person, work, event, group, topic, dimension, proposition, source, passage, claim, editor_note.
- **`object_mode` discriminates the object**: `entity` → `object_type`+`object_id`; `text|number|year|boolean` → exactly one `value_*` column populated (validator-enforced, `validate_canonical_data.py:1042`).
- **Typing contract:** each claim's `subject_type`/`object_mode`/`object_type` must match its predicate's registration in `predicate_types.tsv` (`validate_canonical_data.py:1024-1047`).
- `certainty` ∈ attested, probable, possible, claimed_tradition, legendary, unknown; `claim_status` ∈ active, deprecated, superseded, rejected, draft — the app filters to `active` nearly everywhere.

**The 25 predicates:** `active_in, addressed_to_place, authored_by, bishop_of, controls_place, coworker_of, event_has_year, event_occurs_at, group_present_at, group_schismed_from, member_of_group, originated_in, participant_in, person_affirms_proposition, person_develops_proposition, person_opposes_proposition, place_presence_status, teacher_of, work_affirms_proposition, work_develops_proposition, work_mentions_proposition, work_opposes_proposition, work_year_start, work_year_end, written_at` (choosing guidance: [predicate-playbook.md](./predicate-playbook.md)).

## Semantic Derivation Chains

The pipeline materializes these inference chains into derived tables — and simultaneously treats them as **redundancy errors** if the conclusion is also asserted directly as a claim:

| Chain | Rule | If asserted directly |
|---|---|---|
| `bishop_of` ⇒ `active_in` same place | R7 | error |
| `controls_place` ⇒ `group_present_at` (overlapping interval) | R5 | error |
| person→proposition redundant with own work's work→proposition | R2 | error |
| entity→proposition ∧ entity→place ⇒ proposition presence at place | R8 | error (if asserted) |
| `authored_by` + `written_at` ⇒ person active at place | — | warn |
| `participant_in` + `event_occurs_at` ⇒ person at place | — | warn |

See [derivation-rules.md](./derivation-rules.md) for the normative rule spec.

## The Validator (`scripts/validate_canonical_data.py`, 2,028 lines)

Single file: validator + derived-table regenerator + report builder. Python 3.9+, **stdlib-only** (no requirements.txt needed).

**CLI:** `--data-dir` (default `<repo>/data`); `--check-markdown/--no-check-markdown` (default **on**); `--scan-root` (default repo root); `--check-sparse [N]`; `--check-evidence`; `--json`; `--rewrite-derived` (accepted but a no-op — rewriting is automatic).

**Exit behavior:** exit 1 if any *errors*; warnings never affect the exit code.

> ⚠️ **The validator is not read-only.** `load()` auto-rewrites source tables that aren't in canonical sort order, and `validate_derived` auto-rewrites stale derived files. Running it can mutate `data/` — this is by design (it is also the derivation step; `npm run data:derive` is an alias of `data:validate`).

**Check catalog (condensed):**

| Category | Enforced |
|---|---|
| Structure | Exact header match per table; canonical row sort (auto-rewrite + warn); non-empty unique PKs. |
| Enums & FKs | All `*_kind`/`*_type`/status enums; every FK (see relationship map below); OSIS validity for `bible_osis` locators and `*osis*` fields. |
| Claims | Predicate typing contract; exactly-one-object rule; symmetric-predicate canonical ordering; `year_end ≥ year_start`; ISO timestamps; duplicate active logical claims (error); overlapping temporal duplicates (warn). |
| Redundancy | R2 / R5 / R7 / R8 as errors; authored-place and participant-place chains as warnings; continuity-merge — touching/overlapping control/presence intervals for the same group+place must be merged (error). |
| Evidence | 'attested' claims need a `supports` link; P1 work-claim support must come from the same work unless lost/fragmentary; P3 aspect appropriateness; P4 `supports`+`background_only` invalid (error); P5 supports needs an excerpt; P6 passage supporting ≥3 propositions (warn); P7 AI-boilerplate note patterns (warn); weight ∈ [0,1]; unique (claim, passage). |
| Reviews | Exactly one review row per claim (error); enum/date validity; latest event vs snapshot consistency (warn); missing review per active claim (warn). |
| Markdown | `[[type:id]]` wiki-link targets FK-validated against entity tables (`bible:` targets OSIS-validated) across TSV fields and repo `.md` files. |
| Derived | Recompute all 6; rewrite if stale (warn); FK + enum check the results. |
| Reports (opt-in) | `--check-sparse`: entities with ≤N active claim links; `--check-evidence`: per-claim quality flags. |

## Audit Subsystem (`data/audit/` — offline tooling, not consumed by the app)

A completed claim-audit campaign generated by `scripts/audit_conjoin.py` (3 phases: source-tier/excerpt preflight → deterministic per-claim flags → batch generation):

- **`batches/batch-001..176.json`** — self-contained "conjoined packets" per claim (claim + resolved entities + evidence + tiers + flags). Queues: 0A high-reuse passage/source audit (001–043), 0B deterministic structural purge (044–047), 1 subject-batched semantic review (048–176).
- **`findings.ndjson`** — append-only ledger, 2,430 findings (`{claim_id|passage_id, issue_codes[], recommended_action, confidence, applied, batch_id, note}`).
- **`progress.tsv`** — 142 rows of batch status/outcome counters (partially maintained; predates final batch regeneration to 176).
- **`passage_metadata.tsv`** (531), **`high_reuse_watchlist.tsv`** (56) — phase-0 outputs.
- Narrative snapshots: `audit-plan.md`, `mid-audit-review.md`, `phase2-completion-snapshot.md` ("Phase 2 COMPLETE — all 176 batches processed"), `batch-summary.md`.
- **`scripts/apply_0b_supersede.py`** — one-shot mutator that superseded 27 hardcoded derivable claims (R2/R8), deleted their evidence, appended approved reviews/events, and logged findings.

`data/old/` holds pre-audit snapshots of `claims.tsv` (2,279 rows), `claim_reviews.tsv` (2,271), `claim_review_events.tsv` (3,764) as a rollback baseline — the campaign pruned/superseded ~126 claims.

## Essays (`data/essays/`)

Five long-form markdown essays (53–87 lines each): `apostolic-succession`, `church-went-astray`, `eucharist-center`, `infant-baptism`, `religion-of-the-apostles`. **No frontmatter** — identity is the filename slug; each opens with an H1. ## ID & Relationship Conventions

**IDs:** entity IDs are human-readable kebab-case slugs with no table prefix (`person:origen-of-alexandria` style pairs). Synthetic prefixes: claims `clm-*`, passages `psg-*`, sources `src-*`, editor notes `note-*`; derived rows use content hashes (`edge-<sha1[16]>`, `drv-<sha1>`, `state-<sha1>`).

**Relationship map (validator-enforced):**

```
topics ←─ dimensions ←─ propositions          works ←─ sources ←─ passages
   ▲            ▲______________|                 ▲
   └─ propositions.topic_id                     claims.subject/object (type,id) ──▶ any entity table
places.parent_place_id ─▶ places (self)         claims.context_place_id ─▶ places
claims.predicate_id ─▶ predicate_types          claim_evidence ─▶ claims + passages
claim_reviews / claim_review_events ─▶ claims   editor_notes ─▶ (entity_type, entity_id) + optional claim_id
derived_edges.from/to ─▶ entity tables          note_mentions.mentioned_id ─▶ entity tables (or OSIS)
```

## Runtime Consumption (`src/data/`)

- `parseTsv.ts` — BOM-strip, tab-split, trims cells, `"null"` → null/empty; coercers `int`/`float`/`splitSemi`/`str`. Pipe-split for `supporting_claim_ids`/`derived_edge_ids`; semicolon-split for `name_alt`/`group_presence_summary`.
- `dataStore.ts` — module singleton: parses all 22 tables once at import, builds ~20 `Map` indexes (by-ID, by-subject/object `"type:id"`, by-place, by-decade, evidence-by-claim, …), exposes namespaced accessors + business helpers + `globalSearch`. Decade axis = data decades ∪ forced 0–100 range.
- **Known defect found during scan:** `parsePresence` (`src/data/dataStore.ts:58`) omits `"possible"` from its allow-list, so any `possible` presence_status in `place_state_by_decade.tsv` is coerced to `"unknown"` at runtime. Fix candidate for the next UI pass.
