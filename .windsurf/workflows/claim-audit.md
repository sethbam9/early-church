# Claim Audit Workflow

Invoke with: `/claim-audit batch-NNN`

## Prerequisites

- `data/audit/batches/batch-NNN.json` exists (generated by `scripts/audit_conjoin.py`)
- `data/audit/progress.tsv` shows batch as `pending` or `in_progress`
- Canonical data files are in a clean state (validator passes)

---

## Step 1 — Load batch

1. Read `data/audit/batches/batch-NNN.json`.
2. For each claim packet, display a compact summary:
   - `claim_id` | predicate | subject → object | certainty | year range
   - Flags (from deterministic checks)
   - Evidence count, excerpt_form, source_tier
3. Update `data/audit/progress.tsv`: set batch status to `in_progress`, `started_at` to now.

---

## Step 2 — Queue-specific focus

### If Queue 0A (high-reuse passage/source audit)
- The batch focuses on specific high-reuse passages listed in `focus`.
- For each high-reuse passage:
  1. Read the full passage excerpt.
  2. Verify the locator is correct by checking the source URL.
  3. Verify excerpt accuracy — if paraphrase, fetch the source and compare.
  4. Verify source_kind classification (fix misclassified web_page → primary_text etc.).
  5. Note any issues in `data/audit/findings.ndjson`.
- Claims in the batch are shown for context; they will get full semantic review in Queue 1.
- Do NOT write claim reviews for Queue 0A claims — they will be reviewed later.

### If Queue 0B (deterministic structural purge)
- Claims have high-confidence structural flags (REDUNDANT_*, EXACT_DUPLICATE, CONTINUITY_MERGE, NO_EVIDENCE).
- For each claim:
  1. Verify the flag is correct by inspecting the claim and its evidence.
  2. If REDUNDANT_* or EXACT_DUPLICATE: set `claim_status=superseded` in claims.tsv. Delete evidence rows.
  3. If CONTINUITY_MERGE: merge year ranges into the surviving claim. Set others to `superseded`.
  4. If NO_EVIDENCE with no reasonable fix: set `claim_status=rejected`.
  5. Write review with `review_status=approved`, note explaining the structural resolution.
  6. Log finding to `data/audit/findings.ndjson`.
- Write controversial or ambiguous decisions to `editor_notes.tsv`.

### If Queue 1 (subject-batched semantic review)
- Follow full Steps 3–6 below.

---

## Step 3 — Meta-relationship evaluation (Queue 1 only)

For the batch as a whole:
- **Duplicates**: Any claims semantically identical or near-identical to each other or to already-reviewed claims?
- **Redundancy**: Any R5–R8 violations not caught by deterministic flags?
- **Continuity**: Adjacent time-range claims that should be merged?
- **Supersession**: Stronger claim makes a weaker one unnecessary?

Action: Mark claims as `superseded` or `rejected` as needed.

---

## Step 4 — Per-evidence-row semantic evaluation (Queue 1 only)

For each surviving claim, evaluate every evidence row:

### 4a. Excerpt-only entailment
Read the passage excerpt (or excerpt_override). Decompose the claim into hypotheses:
- **H-subject**: Does excerpt mention the claim's subject?
- **H-predicate**: Does excerpt contain predicate-relevant content?
- **H-object**: Does excerpt mention the claim's object?
- **H-date/place**: Does excerpt support the claimed time/place?
- **H-whole**: Does excerpt support the full atomic claim?

Verify and fix:
- `evidence_role`: supports only if H-predicate passes; else contextualizes or delete
- `support_aspect`: whole_claim only if H-whole passes; downgrade to predicate/subject/object/context as needed
- `assertion_mode`: explicit only if directly stated; strong_inference if clearly implied; weak_inference if requires reasoning
- `evidence_weight`: assign per the rubric in the plan (tier × form × aspect × mode)

### 4b. Paraphrase-risk escalation
If excerpt_form=`paraphrase` AND (support_aspect=`whole_claim` OR assertion_mode=`explicit`):
- **Mandatory**: fetch the source URL and verify the paraphrase against the actual text.
- If paraphrase overstretches: fix excerpt, add notes, or downgrade support_aspect/assertion_mode.
- If paraphrase omits subject/predicate/object: downgrade support_aspect.

### 4c. Locator-context verification
If excerpt seems partial or questionable:
- Check the broader section at the cited locator via source URL.
- If broader section supports claim but excerpt doesn't → fix excerpt or add excerpt_override.
- If broader section also doesn't support → fix or delete the evidence row.

### 4d. Source/link verification
For accessible source URLs:
- Verify URL points to the correct work.
- Verify locator matches a real section.
- Flag and fix: LOCATOR_WRONG_SECTION, SOURCE_URL_WRONG_WORK, EXCERPT_NOT_IN_LOCATOR.

### 4e. Lost/fragmentary work exception
For works tagged as lost/fragmentary (papias-fragments, marcion-antitheses, marcion-gospel, diatessaron, philostorgius-ecclesiastical-history):
- Cross-work support is valid if the later source explicitly attributes content to the lost work.
- Do NOT flag P1 source mismatch in these cases.

---

## Step 5 — Apply edits

Use the `/data-edit` workflow rules for all canonical TSV edits.

For each claim in the batch, apply exactly one action:

| Action | Steps |
|--------|-------|
| **REJECT** | Set `claim_status=rejected` in claims.tsv. Delete all evidence rows for that claim. Log to findings.ndjson. |
| **SUPERSEDE** | Set `claim_status=superseded` in claims.tsv. Delete evidence rows. Log to findings.ndjson. |
| **DELETE evidence** | Delete the specific evidence row from claim_evidence.tsv. |
| **FIX fields** | Edit certainty, evidence_role, support_aspect, assertion_mode, evidence_weight, excerpt_override, notes, locator, etc. |
| **KEEP** | No edits needed. |

**Do NOT delete orphaned passages/sources.** Defer to final cleanup pass.

Write controversial or important decisions to `editor_notes.tsv`:
- `note_kind`: `audit_decision`
- `entity_type` / `entity_id`: the relevant entity
- `claim_id`: the claim being audited
- `body_md`: explain the reasoning
- `created_by`: `cascade-audit-v2`
- `created_at`: ISO 8601 now

---

## Step 6 — Write reviews

For every surviving active claim in the batch:

### 6a. Upsert `claim_reviews.tsv`
- `claim_id`: the claim
- `reviewer_id`: `cascade-audit-v2`
- `review_status`: `approved` | `reviewed` | `needs_revision` | `disputed`
- `reviewed_at`: current ISO 8601 timestamp
- `confidence`: `low` | `medium` | `high`
- `note`: specific finding — never a generic placeholder

### 6b. Append `claim_review_events.tsv`
- `claim_id`, `event_type`, `actor_id`: `cascade-audit-v2`, `event_at`, `note`

### Review criteria
- `approved` + `high`: all evidence directly supports the claim with correct fields
- `approved` + `medium`: evidence correct but could be stronger; or has unscored weights
- `reviewed` + `medium`: acceptable but minor concerns
- `needs_revision` + `low/medium`: evidence weak, fields need fixing, or claim needs splitting
- `disputed`: scholarly consensus contradicts the claim

### Confidence caps
- Paraphrase-only support: cap at `medium` unless paraphrase verified against source
- Tertiary-only support: cap at `low` for doctrinal/person claims, `medium` for infrastructure
- Unscored weight: cap at `medium` until weight assigned

---

## Step 7 — Validate and update progress

// turbo
1. Run: `python3 scripts/validate_canonical_data.py --data-dir data --scan-root data/sheets`
2. If errors: fix them before proceeding. Re-validate until clean.
3. Update `data/audit/progress.tsv`:
   - Set batch `status` to `done`
   - Fill in: `claims_approved`, `claims_needs_revision`, `claims_rejected`, `claims_superseded`, `claims_reopened`, `claims_fixed`, `evidence_fixed`, `evidence_deleted`, `passages_fixed`, `sources_fixed`, `blocking_issue_count`, `advisory_issue_count`, `top_issue_codes`, `completed_at`
4. Append all findings to `data/audit/findings.ndjson` (one JSON line per finding).

---

## Reopening earlier claims

If this batch reveals a duplicate/shared-passage/contradiction with an already-reviewed claim:
1. Reopen the earlier claim's review: append event_type=`reopened` to claim_review_events.tsv.
2. Re-evaluate and update claim_reviews.tsv.
3. Increment `claims_reopened` in the current batch's progress row.
4. Log to findings.ndjson.
